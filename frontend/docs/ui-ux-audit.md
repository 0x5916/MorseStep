# Frontend UI/UX backlog

Reviewed against the current source on 6 October 2026. Findings below are source-confirmed implementation gaps or explicit acceptance requirements; browser reproduction and remediation verification remain required. This is a frontend design/correctness backlog, not a security audit.

## Implemented baseline

The Learn dashboard now has one page-padding owner, localized heading/path/status/disclosure/practice copy, nearby course rows with expandable earlier/later lessons, and a width-constrained recommendation skeleton. New-device guidance uses the existing 60-day attempt query, not lifetime history. Recommendation/session/practice/progress localization is still incomplete.

Home now introduces guided recognition with a curriculum-derived first-lesson preview before the hero actions, device-local progress reassurance, and an outlined secondary Practice action in all five locales. The preview plays K/M sounds on request with synchronized introductory patterns; after both samples finish, an optional two-choice quiz hides answer-revealing cues during recall. Destination rows have icons and explicit link affordances. The centered hero retains quieter local telegraph-key, antenna, and radio-station illustrations on desktop and hides artwork on narrow screens, which use bottom navigation. The desktop header begins at 800px with 44px control targets and a named landmark. Generation prompts are recorded in [home-artwork-prompts.json](home-artwork-prompts.json).

Progress and progression share batch mastery indexing; Learn preserves incremental reduction and its early exit. Saved-session restoration and guided server sync remain pending.

Guided feedback now uses the attempt's correctness independently of speed classification, including unmeasured warm-up answers. Expected and comparison sounds use controller-owned feedback playback without recording another attempt. Typing hints describe automatic submission, incomplete groups remain editable, and keyboard handlers guard composition, held keys, modifiers, and native activation. Misleading grid number hints were removed. A full 15-prompt lesson, both comparison sounds, pause/resume, and a fresh same-lesson retry were verified in the browser on 7 October 2026.

## Remaining packets

### Homepage optimization plan

The current P0 packet moves the first-lesson interaction before the CTAs, shortens the hero copy, and places device-local reassurance directly below the CTAs. The [homepage](../src/routes/+page.svelte) keeps a flat preview card, widens it to 32rem on desktop, and removes the mobile artwork's vertical footprint. K/M patterns may follow [audio-plan timing](../src/lib/training/timing.ts) during the introduction only; an optional two-choice quiz becomes available after both samples finish and hides every answer-revealing pattern during recall.

Acceptance for this packet: the card and one-tap sound controls are visible at 375×667 and 1440×900; text/control contrast passes in both themes; all five locales fit; keyboard focus and activation work; playback, animation, and pending callbacks stop on hide, navigation, and unmount. Use existing [color and focus tokens](../src/app.css) and the [audio engine](../src/lib/audio/engine.ts). Browser checks and the required frontend gates must pass before marking this packet complete.

Later packets remain separate:

- **P0:** simplify [desktop navigation](../src/routes/+layout.svelte), including the guest/theme/language controls and secondary destinations.
- **P1:** refine decorative imagery, bring How it works into view, add a curriculum-based roadmap, and review mobile navigation icons and safe-area behavior.
- **P2:** design measurement for first-listen time/rate, learning CTA conversion, Lesson 1 completion, and device-specific bounce. No existing analytics hook/provider was found; a new dependency or backend API requires approval.
- **P2:** verify first-tap audio on iOS and recovery guidance; validate [offline caching](../src/service-worker.ts), PWA discovery/installability, performance, screen-reader behavior, and Lighthouse accessibility on real devices. These are future acceptance work, not verified claims.
